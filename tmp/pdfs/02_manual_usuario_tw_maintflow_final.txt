TW MaintFlow

Manual de uso

1. Objetivo del manual
Orientar la instalación y el uso de TW MaintFlow por parte de administradores, personal de recepción y técnicos. Los pasos se basan en la versión funcional tw_maintflow_simple,
probada en Windows 11 con XAMPP.

2. Descripción del sistema
TW MaintFlow administra clientes, sedes, equipos, técnicos, órdenes de servicio, repuestos, usuarios y reportes. Las opciones visibles cambian según el rol. La aplicación
conserva la trazabilidad del equipo atendido, la falla informada, el responsable, el diagnóstico, la solución, los repuestos y el costo.

3. Requisitos previos
Windows 10 u 11.
XAMPP con Apache, PHP y MySQL/MariaDB.
phpMyAdmin habilitado.
Navegador moderno (Chrome, Edge o equivalente).
Puerto 80 disponible para Apache y puerto 3306 para MariaDB, salvo configuración distinta.

4. Instalación
1. Copiar la carpeta tw_maintflow_simple dentro de C:\xampp\htdocs.
2. Abrir el panel XAMPP e iniciar Apache y MySQL.
3. Abrir http://localhost/phpmyadmin/.
4. Seleccionar Importar y cargar C:\xampp\htdocs\tw_maintflow_simple\database.sql.
5. Confirmar que existe bd_tw_maintflow con doce tablas.
6. Abrir http://localhost/tw_maintflow_simple/.
Nota: La configuración incluida usa el usuario MariaDB root sin contraseña,
configuración habitual del XAMPP local. Si el equipo utiliza otra credencial,
debe actualizarse config.php.

5. Estructura de usuarios
5.1. Administrador
Consulta y gestiona todos los módulos. Es el único rol autorizado para usuarios y
reportes.

5.2. Recepción
Registra clientes, sedes, equipos y órdenes, y asigna técnicos. No administra usuarios, reportes, repuestos ni técnicos.

5.3. Técnico
Consulta las órdenes asignadas a su cuenta. Puede registrar diagnóstico, solución,
observaciones, estado y actividades; no accede a catálogos administrativos.

6. Inicio de sesión
1. En la portada, seleccionar Abrir el sistema o Ingresar.
2. Escribir el usuario en minúsculas.
3. Escribir la contraseña respetando mayúsculas y minúsculas.
4. Pulsar Ingresar.
5. Verificar que el encabezado muestre el nombre y el rol correctos.
Si las credenciales no coinciden, el formulario muestra Usuario o contraseña incorrectos.

7. Cierre de sesión
Seleccionar Cerrar sesión en el menú lateral. El sistema vacía la sesión, destruye la
cookie correspondiente y regresa al login. No debe cerrarse únicamente la pestaña en
equipos compartidos.

8. Uso del dashboard
El dashboard muestra seis indicadores: clientes activos, equipos, técnicos activos,
órdenes, repuestos con stock bajo y costo acumulado. El menú lateral contiene solo las
opciones autorizadas.

9. Módulo de clientes
Listar y buscar visualmente
Ingresar a Clientes. La tabla presenta razón social, RUC, contacto, teléfono, correo,
dirección y estado.

Crear
1. Pulsar + Nuevo cliente.
2. Completar razón social y RUC; añadir datos de contacto.
3. Pulsar Guardar.
4. Confirmar el mensaje Cliente guardado y el registro en la tabla.

Editar o desactivar
Usar Editar para modificar datos. La desactivación requiere confirmación y conserva
el registro para mantener relaciones históricas.

10. Módulo de sedes
Cada sede pertenece a un cliente. Para crearla, seleccionar + Nueva sede, elegir el
cliente y completar nombre, dirección, distrito, provincia y departamento. La tabla
muestra la razón social asociada.

11. Módulo de equipos
El módulo registra activos físicos. Para crear un equipo:
1. Pulsar + Nuevo equipo.
2. Elegir sede y categoría.
3. Escribir código único, nombre, marca, modelo y número de serie.
4. Indicar fecha de adquisición, estado operativo y observaciones.
5. Guardar y verificar el registro.

12. Módulo de categorías
Las categorías se almacenan en categorias_equipo y alimentan la lista del formulario de equipos. La versión actual no incorpora una pantalla CRUD independiente para
categorías. Si se requiere ampliar el catálogo durante la exposición, se debe hacer en la
base o implementar previamente un controlador, modelo, vista y ruta específicos; no
se recomienda editarlo durante una demostración.

13. Módulo de técnicos
El administrador puede listar, crear, editar y desactivar técnicos. Un técnico se vincula con una cuenta de usuario de rol tecnico; además se registran especialidad, teléfono
y fecha de ingreso.

Figura 12: Listado de técnicos activos y sus especialidades.

14. Módulo de órdenes de servicio
14.1. Creación
Administrador o recepción seleccionan + Nueva orden, eligen equipo, técnico y estado, indican mantenimiento preventivo o correctivo, prioridad, fecha programada, falla
y costo de mano de obra.

14.2. Asignación
La asignación se realiza al crear la orden mediante el técnico seleccionado. El técnico
autenticado verá únicamente las órdenes relacionadas con su usuario.

14.3. Prioridad
Las prioridades son Baja, Media, Alta y Crítica. Deben reflejar el impacto real para
que la lista sea útil en la planificación.

14.4. Diagnóstico y solución
En Ver, el técnico escribe diagnóstico, solución y observaciones. Estos campos no
deben confundirse: el diagnóstico explica la causa y la solución documenta la intervención.

14.5. Estado y cierre
El estado sigue el catálogo Pendiente, Asignada, En proceso, En espera y Cerrada.
Al finalizar, el usuario autorizado selecciona Cerrada y registra la solución. La base
también contiene sp_cerrar_orden como operación SQL especial, aunque la interfaz
usa la actualización del modelo.

15. Detalle de orden
El detalle presenta equipo, técnico, estado, descripción, diagnóstico, solución, observaciones, mano de obra y costo total. La sección de actividades permite indicar descripción, repuesto opcional, cantidad y precio. Al insertar un repuesto, el trigger descuenta
stock y recalcula el costo.

Figura 15: Detalle de una orden con formularios técnicos.

16. Módulo de repuestos
El administrador gestiona código, nombre, descripción, unidad de medida, stock
actual, stock mínimo y precio. Un stock actual menor o igual al mínimo aparece en el
reporte de alerta.

17. Movimientos de stock
La tabla movimientos_repuesto registra entradas, salidas y ajustes con cantidad,
motivo, fecha y referencia. La versión seleccionada conserva el historial en base de datos,
pero no incorpora una pantalla CRUD exclusiva. El consumo asociado a una orden se
registra en detalle_orden y el trigger actualiza repuestos.stock_actual.

18. Gestión de usuarios
Solo el administrador puede acceder. La pantalla lista usuario, nombres, correo, rol
y estado. Las nuevas contraseñas se almacenan como hash; para retirar acceso se usa
desactivación lógica.

Figura 18: Gestión de cuentas y roles.

19. Reportes
El reporte presenta métricas generales, órdenes agrupadas por estado, órdenes por
técnico y repuestos con stock bajo. Los valores proceden de COUNT, SUM, GROUP BY, INNER
JOIN y LEFT JOIN.

20. Validaciones
Campos requeridos en formularios HTML.
Conversión de identificadores a enteros y costos a números.
Rechazo de costos o cantidades negativas.
Token CSRF en solicitudes POST.
Confirmación JavaScript antes de acciones sensibles de desactivación.
Escape HTML mediante e() para datos presentados.
Restricción de usuario técnico a órdenes asignadas.

22. Error 403
El error 403 significa que la sesión es válida, pero el rol no tiene permiso. La prueba
se realizó ingresando como recepción y abriendo Reportes. Debe usarse Volver y continuar con las opciones permitidas.

Figura 20: Respuesta 403 obtenida con una cuenta de recepción.

23. Error 404
El error 404 indica que la combinación de controlador y acción no existe en rutas.php.
Revisar la URL o volver al dashboard.

Figura 21: Respuesta 404 ante una ruta inexistente.

25. Evidencias para exposición
Antes de sustentar se recomienda demostrar esta secuencia:
1. Mostrar XAMPP activo y bd_tw_maintflow con doce tablas.
2. Ingresar como administrador y presentar indicadores y módulos.
3. Crear o editar un cliente sin alterar información crítica.
4. Mostrar una orden, su técnico, diagnóstico, solución y detalle.
5. Enseñar el trigger en phpMyAdmin y explicar el descuento de stock.
6. Cerrar sesión e ingresar como recepción; intentar Reportes y mostrar 403.
7. Ingresar como técnico y comprobar que solo ve sus órdenes.
8. Explicar 404, prepared statements y utf8mb4.

26. Conclusiones del manual
El uso correcto de TW MaintFlow depende de iniciar los servicios, importar la base
y respetar el rol asignado. Los módulos siguen una navegación uniforme y las validaciones reducen errores comunes. La versión documentada fue recorrida con las tres cuentas, por lo que las pantallas y restricciones descritas corresponden al comportamiento
observado.
